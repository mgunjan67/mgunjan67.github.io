# Portfolio content boundary

Showcase independently owned, publicly released work and original portfolio experiments. Reading a local project, resume, chat, or file does not authorize publishing it.

Keep employment references to company name, job title, dates, and other explicitly approved public professional facts. Do not infer permission to disclose employer or client projects from an employee's involvement. Do not publish internal names, implementation methods, architecture, unreleased results, screenshots, customer imagery, datasets, or private source code. An abstract illustration or renamed case study does not make an internal project suitable for publication.

Use `public-content.json` for public source provenance and the exact deployment asset list. Add content only after confirming ownership and the applicable public release or explicit user authorization. Do not use local unreleased manuscript revisions to expand descriptions of a public paper. Do not upload resumes that include unapproved employer/client details.

Build output must be cleaned before rebuilding and must contain only explicitly listed assets. Review the entire public Git history before publishing a replacement branch. A commit that deletes a private asset does not remove it from earlier commits.
